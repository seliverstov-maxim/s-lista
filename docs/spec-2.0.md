# Спецификация 2.0: режимы тренировки и пьесы

Согласовано 26 сентября 2026. **Ещё не реализовано.** Документ описывает, что меняется относительно версии 1.0 ([requirements.md](requirements.md)). Когда часть реализована, её требования переносятся в `requirements.md`, а решения — в [decisions.md](decisions.md).

## Что меняется

- Приложение открывается на главном экране, а не сразу на упражнении.
- Два режима тренировки: «Случайные ноты» и «Пьесы».
- Настройки случайных нот упрощены: ключ выбирает руку, диапазон задают добавочные линейки.
- Пьесы — одноголосные мелодии из MusicXML. Их проверяет и добавляет в репозиторий локальный инструмент.
- Аккордов нет: в каждый момент нужно сыграть одну ноту. Экранная клавиатура работает в обоих режимах.

Проверка ответа (FR-CHK), микрофон, калибровка и MIDI (FR-IN, FR-CAL) не меняются, кроме FR-PC-07.

## Экраны и навигация (FR-NAV)

**FR-NAV-01. Экраны.**
1. Главный: «Продолжить» (если уже что-то выбирали), «Случайные ноты», «Пьесы», «Прогресс», «Настройки».
2. «Случайные ноты»: настройки генератора (FR-RND-01) и кнопка «Начать».
3. «Пьесы»: список пьес (FR-PC-03).
4. Тренажёр.

Критерии:
- Дано: первый запуск. Тогда открыт главный экран без кнопки «Продолжить». (e2e)
- Дано: пользователь играл случайные ноты «Басовый, 1 линейка снизу, 2 сверху». Когда сайт открыт снова и нажато «Продолжить», тогда открыт тренажёр с этими настройками. (e2e)

**FR-NAV-02. Возврат.** В тренажёре есть кнопка «Назад». Она ведёт на экран, с которого пришли (настройки случайных нот или список пьес), а оттуда — на главный. Системная «Назад» (кнопка или жест Android) работает так же и с внутренних экранов не уводит с сайта.
- Дано: открыт тренажёр пьесы. Когда выполнен `history.back()`, тогда открыт список пьес. (e2e)

**FR-NAV-03. Общие настройки.** Названия нот, «Требовать точную октаву», показ клавиатуры, звук клавиш, микрофон (калибровка и порог) и MIDI. Открываются с главного экрана и из тренажёра, действуют в обоих режимах.

**FR-NAV-04. Прогресс.** Панель «Прогресс» (FR-ST-02) открывается с главного экрана и из тренажёра. «Это занятие» считается с открытия сайта, по всем режимам вместе.

**FR-NAV-05. Шапка тренажёра.** Показывает, что сейчас играется: например, «Скрипичный · линейки: 1 снизу, 2 сверху» или «ABC Song · басовый ключ».

## Случайные ноты (FR-RND)

**FR-RND-01. Настройки генератора.** Их четыре:
- ключ: «Скрипичный — правая рука» или «Басовый — левая рука»;
- добавочные линейки снизу: от 0 до 3;
- добавочные линейки сверху: от 0 до 3;
- «Чаще давать трудные ноты» (FR-ST-03).

Убираются: большой стан, готовые уровни (FR-SET-01), выбор диапазона по нотам, «Диезы и бемоли», «Плавно, до квинты», режим «По одной». Генератор даёт только белые клавиши, ходы любые, ноты всегда идут строкой (FR-EX-01).

**FR-RND-02. Диапазон.** Число линеек — сколько добавочных линеек можно дорисовать. Крайняя нота стоит на последней разрешённой линии: при 0 — на крайней линии стана, при N — на N-й добавочной линейке. Под ней и над ней нот нет: при 0 все ноты лежат в пределах стана.

Формула для ступени `d`: `bottomD − 2·N ≤ d ≤ bottomD + 8 + 2·M`, где `bottomD` — нижняя линия стана (раздел 4 [architecture.md](architecture.md)), N — линеек снизу, M — сверху.

| Ключ | Линеек | Нижняя нота | Верхняя нота |
|---|---|---|---|
| Скрипичный | 0 | ми¹ (E4) | фа² (F5) |
| | 1 | до¹ (C4) | ля² (A5) |
| | 2 | ля (A3) | до³ (C6) |
| | 3 | фа (F3) | ми³ (E6) |
| Басовый | 0 | Соль (G2) | ля (A3) |
| | 1 | Ми (E2) | до¹ (C4) |
| | 2 | До (C2) | ми¹ (E4) |
| | 3 | Ля₁ (A1) | соль¹ (G4) |

Критерии:
- Дано: 1000 нот, «Басовый», 3 линейки снизу и 3 сверху. Тогда все ноты — белые клавиши от Ля₁ до соль¹, двух одинаковых подряд нет. (авто, unit-тест генератора)
- Дано: «Скрипичный», 0 снизу и 0 сверху. Тогда ни одной добавочной линейки на стане нет. (авто)

Микрофон проверен от до большой октавы (C2, FR-IN-02). Басовый ключ с 3 линейками снизу опускается ниже, до Ля₁ и Си₁, — и в генераторе, и в пьесах. Эти ноты нужно добавить в тесты распознавания.

**FR-RND-03. Выдача.** Как FR-EX-04, но без знаков альтерации и без плавного режима: ноты случайные, одна клавиша не повторяется подряд (на этом держится защита от отголосков, ADR-04). При «Чаще давать трудные ноты» веса считаются по FR-ST-03.

**FR-RND-04. Перенос сохранённых настроек.** Большой стан превращается в скрипичный ключ. Старый диапазон переводится в линейки: берётся наименьшее число линеек, при котором старая граница попадает в диапазон, но не больше 3. Поля `acc`, `motion` и `perRow` удаляются. Статистика (`slista.stats.v1`) не меняется.

## Пьесы (FR-PC)

**FR-PC-01. Что такое пьеса.** Одна мелодическая линия на одну руку: одна партия, один стан, один голос, без аккордов.

**FR-PC-02. Версии для двух ключей.** У каждой пьесы до двух версий: для скрипичного и для басового ключа. Версия — это мелодия, сдвинутая на целое число октав. Ключи из исходного файла не учитываются.

Линейки в пьесах не настраиваются, и настройки генератора на пьесы не влияют. Для пьес всегда разрешено 3 линейки снизу и 3 сверху по правилу FR-RND-02. Поэтому диапазон версии такой:
- скрипичный ключ — от фа (F3) до ми³ (E6);
- басовый ключ — от Ля₁ (A1) до соль¹ (G4).

Выбирается сдвиг, при котором самой крайней ноте нужно меньше всего линеек. При равенстве выбирается вариант, где меньше нот на добавочных линейках, затем меньший сдвиг. Версия, которой трёх линеек не хватает, не публикуется.
- Дано: мелодия от до¹ до до². Тогда скрипичная версия без сдвига, басовая — на октаву ниже (от до до до¹). (авто, тест инструмента)

**FR-PC-03. Список пьес.** У каждой пьесы: название, автор и кнопки опубликованных версий — «Скрипичный» и «Басовый». В приложении пьесы не настраиваются.

**FR-PC-04. Нотная запись — как в файле.** Показываются:
- размер и его смена;
- ключевые знаки (до 7) и их смена;
- длительности от целой до шестнадцатой, с точками; восьмые и шестнадцатые сгруппированы, как в файле;
- паузы и затакт;
- лиги между нотами одной высоты;
- случайные знаки: диез, бемоль, бекар.

Не показываются: динамика, штрихи, фразировочные лиги, аппликатура, текст, темп.

**FR-PC-05. Строки.** В строку помещается столько целых тактов, сколько влезает при межстрочном интервале не меньше ~11 px (как в FR-EX-01). Такт, который не помещается целиком, переносится на следующую строку по границе доли. Каждая строка начинается с ключа и ключевых знаков, размер пишется в первой строке и там, где он меняется. Когда строка сыграна, открывается следующая, как сейчас.
- Дано: ширина листа 327 px, такт 4/4 из восьми восьмых. Тогда такт занимает больше одной строки, разрыв приходится на границу доли, а межстрочный интервал не меньше 11 px. (e2e)

**FR-PC-06. Игра.** Тренажёр ждёт верную ноту и ритм не проверяет. Курсор идёт по нотам и пропускает паузы. Нота, продолженная лигой, — это один удар. Подсказка и пропуск работают как в FR-EX-06, проверка — как в FR-CHK, кроме FR-PC-07. Экранная клавиатура охватывает диапазон версии.

**FR-PC-07. Повтор ноты с микрофона.** В пьесе одна нота может повторяться подряд, и тогда отголосок прошлого удара совпадает с целью. Если текущая нота той же высоты, что только что засчитанная, удар с микрофона засчитывается, только если он уверенный (`strong`) и после прошлой ноты прошло не меньше T мс. Значение T подбирается на настоящем пианино. Для MIDI и экранной клавиатуры ограничений нет.
- Проверка: вручную, пьеса с повторяющимися нотами на пианино.

**FR-PC-08. Конец пьесы.** Итог: сколько нот сыграно с первого раза и за какое время. Кнопки «Ещё раз» и «К списку».

**FR-PC-09. Статистика.** Ноты пьес учитываются в общей статистике и в «трудных нотах» (ключ `clef:d:acc`). «Чаще давать трудные ноты» влияет только на случайные ноты.

**FR-PC-10. Где лежат пьесы.** Отдельными файлами рядом с `index.html` (FR-TOOL-03). Режим «Пьесы» работает, когда сайт открыт по http или https. Если список не загрузился (файл открыт с диска, нет сети), показывается понятное сообщение, а случайные ноты продолжают работать.

## Инструмент загрузки пьес (FR-TOOL)

**FR-TOOL-01. Запуск.** `npm run add-piece -- <файл> [--id …] [--title …] [--composer …] [--license …] [--source …] [--force]`. Принимает `.mxl` (сжатый MusicXML) и `.musicxml`. Название и автор берутся из файла, флаги их переопределяют.

**FR-TOOL-02. Проверки.** Пьеса отклоняется с номером такта и советом, что поправить в MuseScore, если:
- в файле больше одной партии, стана или голоса либо есть аккорды;
- есть триоли и другие нестандартные деления, форшлаги, знаки повтора или вольты, дубль-диезы или дубль-бемоли, длительности короче шестнадцатой;
- длительность такта не совпадает с размером (кроме затакта и последнего такта);
- ни одной версии не хватает трёх линеек (FR-PC-02);
- нет лицензии: ни в файле, ни во флаге `--license`.

Динамика, штрихи, фразировочные лиги, аппликатура, текст и темп отбрасываются без ошибки.

**FR-TOOL-03. Результат.**
- `pieces/<id>.json` — данные для приложения;
- `pieces/src/<id>.mxl` или `pieces/src/<id>.musicxml` — исходник, чтобы пересобрать JSON, если формат изменится;
- запись в `pieces/index.json` — список для экрана «Пьесы».

Существующий `id` без `--force` не перезаписывается. Коммит и публикация (`git push`) — отдельный шаг.

**FR-TOOL-04. Тесты.** Инструмент покрыт тестами на маленьких MusicXML-файлах: верная пьеса, каждая причина отказа, выбор сдвига октавы.

## Данные пьесы (черновик)

```json
{
  "id": "abc-song",
  "title": "ABC Song",
  "composer": "народная",
  "license": "CC0",
  "source": "https://…",
  "shift": { "treble": 0, "bass": -1 },
  "measures": [
    { "time": [4, 4], "key": 0, "pickup": false, "items": [
      { "d": 28, "acc": 0, "len": 4 },
      { "d": 29, "acc": 1, "len": 8, "dots": 1, "tie": true, "mark": 1 },
      { "rest": true, "len": 4 }
    ] }
  ]
}
```

- `shift` — сдвиг версии в октавах. Нет ключа — нет версии.
- `d` и `acc` — ступень и знак, как в приложении (раздел 3 [architecture.md](architecture.md)), до сдвига.
- `len` — вид длительности: 1, 2, 4, 8 или 16; `dots` — число точек.
- `tie: true` — нота продолжается лигой в следующую.
- `mark` — знак, нарисованный перед нотой: −1 бемоль, 0 бекар, 1 диез. Есть, только если знак стоит в файле.
- `time` и `key` (число знаков, минус — бемоли) пишутся в первом такте и там, где меняются.

## Решения

- **ADR-09 (черновик). Пьесы — отдельные статические файлы.** Исходник MusicXML переводится в компактный JSON локальным инструментом. Разбор MusicXML не попадает в `index.html`, а проверки проходят до публикации. Цена: режим «Пьесы» не работает, если открыть `index.html` с диска. Нужно уточнить ADR-01 и инвариант «один файл» в `CLAUDE.md`.
- **ADR-10 (черновик). Ключ — это рука, диапазон — добавочные линейки.** Большой стан и готовые уровни убраны ради простоты настроек.

## План работ

1. Навигация, общие настройки, упрощённый генератор, перенос настроек; e2e.
2. Инструмент `add-piece`: чтение `.mxl` и MusicXML, проверки, JSON; тесты.
3. Нотный движок: длительности, паузы, точки, флажки и группировка, ключевые знаки, размер, строки с переносом такта; новые знаки Bravura (ADR-02).
4. Режим пьесы в тренажёре: курсор, паузы и лиги, конец пьесы, статистика, FR-PC-07; e2e.
5. Тесты распознавания для Ля₁ и Си₁. Обновить `requirements.md`, `decisions.md`, `architecture.md`, `testing.md` и `CLAUDE.md`.
