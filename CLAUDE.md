# CLAUDE.md

«С листа» — тренажёр чтения нот для пианиста. Два режима: случайные ноты (ключ — рука, диапазон — добавочные линейки) и пьесы для одной руки. Показывает ноты на стане, слушает пианино через микрофон (или MIDI) и проверяет сыгранное. Статическое одностраничное приложение на чистом JS. Сайт: https://seliverstov-maxim.github.io/s-lista/ (GitHub Pages из корня `main`).

## Команды

```bash
npm run build      # src/ → index.html (обязательно после любых правок в src/)
npm test           # распознавание звука, нотный движок, инструмент пьес, ~20 с, без зависимостей
npm install && npx playwright install chromium   # один раз, для e2e
npm run test:e2e   # Chromium: экраны, пьеса целиком, MIDI-заглушка, калибровка с искусственным микрофоном
npm run serve      # http://localhost:8080 — микрофон работает на localhost
npm run add-piece -- файл.mxl [--license "CC0 1.0"] [--check]   # добавить пьесу из MusicXML
npm run add-piece -- --rebuild                                   # пересобрать все пьесы после смены формата
```

## Где что лежит

- `src/app.html` — разметка, стили, экраны, тренажёр, микрофон, калибровка, MIDI в одной IIFE. Разделы помечены `/* ---------- Название ---------- */`. Карта разделов — в `docs/architecture.md`, раздел 2.
- `src/music.js` — чистые функции без DOM: теория, диапазон по линейкам, генератор, партитура, нотный движок (раскладка по строкам и SVG). Тестируется в Node.
- `src/detector.js` — распознавание: YIN, БПФ, `harmonicPick`, класс `PitchListener`. Не зависит от DOM, тестируется в Node.
- `src/glyphs.json` — контуры нотных знаков Bravura (SMuFL), в межстрочных интервалах. Генерируется `scripts/extract-glyphs.py`.
- `index.html` — **сгенерированный** файл, но хранится в git: его раздаёт Pages. Руками не править.
- `sounds/piano/` — записи рояля (MP3, CC BY 3.0). **Генерируются** `scripts/make-piano.mjs` из архива Salamander Grand Piano V3; указание автора — в настройках, `README.md` и `sounds/piano/README.md`.
- `pieces/` — пьесы: `index.json` (список), `<id>.json` (данные), `src/` (исходники MusicXML). **Генерируются** `scripts/add-piece.mjs`; руками не править.
- `scripts/add-piece.mjs`, `scripts/lib/` — инструмент загрузки пьес: XML, zip (`.mxl`), проверки и перевод MusicXML.
- `docs/` — требования (FR/NFR/критерии приёмки), архитектура, решения (ADR), тестирование, бэклог, спецификация 2.0 (в том числе формат данных пьесы).
- `tests/detector.test.mjs` — распознавание, `tests/music.test.mjs` — нотный движок и логика, `tests/pieces.test.mjs` — инструмент пьес, `tests/helpers/` — синтез фортепиано, загрузка `detector.js` и `music.js` в Node, `tests/e2e/run.mjs` — Playwright.

## Порядок работы

1. Перед задачей прочитайте нужный раздел `docs/architecture.md` и связанные требования в `docs/requirements.md`.
2. Правьте только `src/`, `scripts/`, `tests/`, `docs/`; пьесы — только через `npm run add-piece`.
3. `npm run build && npm test`. Если трогали интерфейс, нотный движок, калибровку или MIDI, ещё `npm run test:e2e` и посмотрите скриншоты в `tests/e2e/out/`.
4. Если изменилось поведение, обновите `docs/requirements.md` (и `docs/decisions.md`, если это новое решение) в том же коммите.
5. Коммитьте вместе с пересобранным `index.html`. После `git push` сайт обновляется за 1–2 минуты.
6. Распознавание на настоящем пианино автотесты не проверяют. Попросите пользователя пройти чек-лист из `docs/testing.md` и прислать цифры калибровки.

## Инварианты — не ломать

- **Генератор случайных нот не ставит одну клавишу дважды подряд** (`pickNote`, в том числе на стыке строк и при перестройке строки через `ex.prev` в `newRandomRow`). На этом держится защита от отголосков.
- **Отголоски с микрофона — `isEcho` в `src/music.js`.** Удар той же ноты, что засчитана меньше 1,5 с назад, не ошибка. Как верный ответ (в пьесе нота может повторяться) — только уверенный удар не раньше 250 мс. Для экранной клавиатуры и MIDI правило не действует.
- **Ошибку с микрофона засчитываем только при уверенном ударе** (`strong`) и никогда — по легато. Верную ноту принимаем по любому пути. См. `docs/decisions.md`, ADR-04.
- **Шумовой фон считается только по немузыкальным кадрам** (`ap > 0.3`, больше 1,2 с после удара). Иначе он подстраивается под пианино и связная игра теряет ноты. Проверяет тест «мелодия без педали».
- **Во время калибровки** ноты с микрофона не доходят до проверки. **После первой ноты по MIDI** (`midiSeen`) — тоже, пока устройство подключено. При подключении MIDI микрофон выключается.
- **`AudioContext` создаётся по нажатию пользователя** (требование iOS). Микрофон запрашивается без `echoCancellation`, `noiseSuppression` и `autoGainControl`.
- **Микрофон и MIDI работают только по https или на localhost, пьесы — только по http(s).** Во встроенных фреймах (артефакт Claude) микрофон запрещён — должно оставаться понятное сообщение. С `file://` экран «Пьесы» объясняет, что делать, а случайные ноты работают.
- **`localStorage` — только через `store.get/set`** (там `try/catch`). Настройки — `slista.settings.v2` с переносом из v1 (`migrateSettings`), статистика — `slista.stats.v1`. Если меняете формат, поднимайте версию ключа и добавляйте перенос данных.
- **`index.html` — один файл без зависимостей во время работы**, кроме Google Fonts с запасными системными шрифтами, файлов пьес и записей рояля (`sounds/piano/`) с того же сайта. Не добавляйте CDN-библиотеки. Лимит — 150 КБ (NFR-SIZE-01), сборка падает при превышении.
- **Сборка выбрасывает из `<style>` и `<script>` строки, которые начинаются с `//` или целиком состоят из одного `/* … */`, и отступы.** Строка кода не должна начинаться с `//`, даже внутри многострочного шаблона.
- **Правило линеек записано дважды** — `ledgerRange`/`linesNeeded` в `src/music.js` и `ledgerLines` в `scripts/lib/musicxml.mjs`. Меняете одно — меняйте другое; совпадение проверяет тест.
- **Проигрыш пьесы (`pb`): пока звучит, любой ввод игнорируется**, а звук с микрофона — ещё 1,2 с после (`micMuteUntil`): иначе микрофон засчитает динамик. Звук — через `audioOut()`, `AudioContext` создаётся по нажатию.
- **Темп пьесы обязателен** (`tempo` в данных, из `<sound tempo>` или метронома); смена темпа — только в начале такта.
- **История браузера:** экраны и открытые панели — записи в истории, «Назад» в приложении — `history.back()`. Не заменяйте это прямым переключением экранов, иначе системная «Назад» уведёт с сайта.

## Стиль

- Интерфейс и комментарии — на русском: десятичная запятая, «ё», «дБ» через неразрывный пробел. Имена в коде — английские.
- Тексты в интерфейсе пишутся с точки зрения пользователя, коротко, без жаргона. Ошибка объясняет, что сделать.
- Цвета — только через CSS-токены в `:root`. Меняя палитру, обновляйте обе тёмные ветки: `@media (prefers-color-scheme: dark)` и `:root[data-theme="dark"]`.
- Чистый JS без фреймворков. `el.hidden` вместо `style.display`. Нажатия ≥ 44 px. Анимации учитывают `prefers-reduced-motion`.
- Нотация по правилам: штили, рёбра, добавочные линейки, знаки альтерации действуют до конца такта, бекар при отмене. Меняя нотный движок, смотрите скриншоты на телефонной ширине (360–390 px) и на компьютере.

## Полезно знать

- Ступень ноты `d = октава·7 + буква` (до = 0); до¹ = C4 = `d 28` = MIDI 60. Нижняя линия: у скрипичного ключа `d 30` (E4), у басового `d 18` (G2).
- Диапазон по линейкам: `bottomD − 2·N ≤ d ≤ bottomD + 8 + 2·M`. Пьесам всегда разрешено 3 и 3: скрипичный F3–E6, басовый A1–G4.
- Пьеса — одна линия на одну руку. Формат данных — `docs/spec-2.0.md`, «Данные пьесы».
- У пользователя цифровое пианино Roland FP-30 (USB и Bluetooth MIDI) и телефон на пюпитре. На iOS MIDI в браузере недоступен.
- Открытые вопросы и следующие шаги — в `docs/backlog.md`.
